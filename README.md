# beerhappy · Пивной Санта

Мобильное веб-приложение для тайного обмена пивом в закрытой компании 18+. Подходит и для безалкогольного пива. Python 3.11+, SQLite, обычный HTML/CSS/JS; пакеты для запуска не нужны.

## Локальный запуск

```bash
git clone https://github.com/ZuevPU/beerhappy.git
cd beerhappy
python3 server.py
```

Открыть **http://127.0.0.1:8000**. Создать аккаунт, группу и отправить приглашение друзьям. В разработке данные сохраняются в `data/beerhappy.sqlite3`. Для доступа с других устройств задайте `HOST=0.0.0.0` и `PUBLIC_URL`, точно совпадающий с адресом браузера. На публичном сервере нужен HTTPS.

## Реализовано

- Аккаунты по email и паролю (scrypt), сессии в HttpOnly/SameSite cookie; Secure на HTTPS. Самоподтверждение 18+.
- Создание групп, отзываемое приглашение, участие организатора по выбору.
- Бюджет на весь подарок, ровно/минимум/диапазон количества, объём, сроки регистрации, жеребьёвки и передачи. Сроки вводятся в локальном часовом поясе браузера, сохраняются в UTC.
- Ручное пожелание с количествами и допустимостью замены; «удивите меня»; ограничения крепости, алкогольности, вкусов и ингредиентов.
- Вкусовой, ассоциативный и смешанный тесты, общий справочник стилей. Явные вкусовые запреты сильнее игровых ассоциаций.
- ИИ-сомелье через DeepSeek при наличии серверного ключа. До трёх запросов на участника в группе. Ошибки не уничтожают текст формы. Контакты и переписка в API модели не отправляются.
- Ручная и автоматическая жеребьёвка: транзакция, ровно один даритель/получатель, нет самоназначения, защита от повторного запуска. Автозапуск проверяется каждые 20 секунд; при неготовности ждёт и уведомляет организатора.
- Допуск опоздавших с вставкой в существующую пару, обмен получателями, исключение участника с сохранением баланса (после жеребьёвки остаётся минимум 3 участника).
- Две анонимные текстовые переписки, просмотр текущей версии пожеланий. Переназначение закрывает старую карточку/переписку, новый даритель не получает её историю.
- Организатор видит пожелания и пары, но не чужую переписку; завершение не раскрывает дарителей.
- Уведомления внутри приложения, история действий; обновление чата кнопкой.

## Что ещё не подключено

Это первая рабочая версия для закрытого пилота, а не завершение всех пунктов спецификации.

- Подтверждение email, вход по коду и восстановление пароля. Email сейчас служит логином и **не считается проверенным контактом**. Не используйте чужие адреса для регистрации.
- Рассылки email/SMS, Telegram, MAX. Напоминания сейчас появляются только внутри приложения.
- DeepSeek требует ключа; реальные вызовы API без ключа не проверялись.
- Редактирование правил уже созданной группы с повторным подтверждением участниками; для изменения правил пока создайте новую группу.
- Публичная регистрация без приглашений в игру не ограничена отдельным общесервисным листом допуска. До публичного запуска нужны подтверждение контакта, восстановление доступа, правила хранения/удаления персональных данных и ограничение регистрации на уровне reverse proxy.
- Автоматическая очистка адресов/чатов через 90 дней пока не реализована. Не собирать лишние персональные данные в пилоте.
- Браузерная проверка выполнена для стартовой страницы и переключения формы входа; полный путь проверен интеграционными HTTP-тестами.

Ни поставки пива, ни оплата, ни гарантии наличия марок не входят в приложение. Стили и ассоциации развлекательные: состав и крепость конкретного продукта проверяет даритель по этикетке.

## Установка на Ubuntu/Debian

Скрипт запускается **на целевом сервере**. Root-пароль и SSH-ключи в репозитории отсутствуют.

```bash
git clone https://github.com/ZuevPU/beerhappy.git
cd beerhappy
sudo bash deploy/install.sh
```

Без домена приложение слушает только `127.0.0.1:8000`, снаружи вход не открывается. Для первого просмотра выполните **на своём компьютере**:

```bash
ssh -L 8000:127.0.0.1:8000 root@SERVER_IP
```

Откройте http://localhost:8000. Этот локальный режим в `/etc/beerhappy.env` использует `PUBLIC_URL=http://localhost:8000`.

Для публичного HTTPS направьте A-запись своего домена на IP сервера, откройте входящие 80/443 и запустите:

```bash
sudo bash deploy/install.sh beer.example.ru
```

`beer.example.ru` — пример, замените своим доменом. Скрипт установит Nginx/Certbot и предложит получить сертификат, не удаляя другие виртуальные хосты. Порты 25/465/587/2525 не нужны: SMTP пока не подключён.

Секреты и настройки хранятся только в `/etc/beerhappy.env` (0600):

```ini
PUBLIC_URL=https://beer.example.ru
DEEPSEEK_API_KEY=ключ_на_сервере
DEEPSEEK_MODEL=deepseek-flash
```

После изменения: `sudo systemctl restart beerhappy`. Отдельный системный пользователь `beerhappy`, данные в `/var/lib/beerhappy`, код в `/opt/beerhappy`, сервис `beerhappy.service`. `PUBLIC_URL` обязан точно совпадать с адресом браузера: это проверка источника запросов. Для работы внутри MAX в будущем потребуется отдельная политика iframe и привязка аккаунтов.

Проверка и логи:

```bash
curl http://127.0.0.1:8000/api/health
sudo systemctl status beerhappy
sudo journalctl -u beerhappy -n 50
```

Обновление: в исходном checkout выполнить `git pull --ff-only`, затем повторно `sudo bash deploy/install.sh`. Существующие настройки и база сохраняются. Для согласованной резервной копии SQLite:

```bash
sudo -u beerhappy python3 /opt/beerhappy/deploy/backup.py /var/lib/beerhappy/backups/manual.sqlite3
```

Копии содержат данные пользователей и не должны размещаться в публичном каталоге.

## Проверки

```bash
python3 -m unittest discover -s tests -v
python3 -m py_compile server.py domain.py
node --check static/app.js
bash -n deploy/install.sh
```

Тесты выполняют полный HTTP-сценарий на 10 участниках: вход, пожелания, распределение, проверку прав и анонимности, чат, просмотр новой версии, допуск 11-го, смену назначения, отзыв приглашения и завершение. Отдельно проверяются случайные перестановки и конкурентная жеребьёвка. GitHub Actions запускает те же проверки.
